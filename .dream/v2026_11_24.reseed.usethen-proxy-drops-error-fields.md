# 🌙 dream: a `useThen` / `useBeforeAll` value that is an Error or an array reads wrong

kind: reseed · owner: ehmpathy/test-fns · caught 2026-11-24

## .the cue that fired

stone `5.3` refactor to one shared act per `when` (peer r6). `useThen(() => getError(...))`
went red in 13 cases: `error.message` read `undefined`. an earlier round hit the twin: a
`useBeforeAll` array had no `.map`.

## .the gap, precisely

the shared value is a proxy. over an Error it drops the Error's own fields (`message`,
`metadata`); over an array it drops array methods. the read fails at assert time, far from
the cause, with a message that names the wrong defect (`received value must not be null`).

## .the shape of the fix

- in test-fns: forward reads to the resolved value with `Reflect.get(target, key, target)`
  so own and prototype fields both pass; clamp with an Error case and an array case
- or, at least, document the shape rule in the readme: return an object, hold the value
  under a key

## .why it is not done in this round

the fix lives in another repo. the local cure (hold the value under a key) is in place.
