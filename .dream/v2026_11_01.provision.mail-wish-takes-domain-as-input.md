# 🌙 dream: the mail wishes take the mail-domain + mailbox as input

kind: provision · owner: this repo · caught 2026-11-01

## .the cue that fired

peer r8 at i002 of stone `5.1` graded the generalize requirement unmet: the wish says any
domain owner reuses the resources, and the delivered wishes read module constants instead.

## .the gap, precisely

`getResourcesOfMail({ account, region })` and the cloudflare `getResources()` read
`MAIL_DOMAIN`, `MAIL_MAILBOX`, `MAIL_BUCKET`, `MAIL_RULE_SET`, `MAIL_RULE`, `MAIL_CONFIG_SET`
from `provision/resources.common.mail.ts`. a second domain owner must edit that module; no
declaration takes the domain as an input.

## .the shape of the fix

- a `MailDomainSpec` input (domain, mailbox, region) threaded into both wishes
- derive bucket, rule set, rule, and config set names from the spec in one transformer
- one wish file per domain, each a three-line call with its own spec

## .why it is not done in this round

one domain exists today. a parameter-in wish is the abstraction `rule.prefer.wet-over-dry`
asks to defer until a second caller arrives, and every name already derives from one module,
so the lift stays mechanical. recorded as a deviation in the 5.1 yield.
