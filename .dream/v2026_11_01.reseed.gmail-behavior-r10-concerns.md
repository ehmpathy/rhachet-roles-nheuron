## .the gap, precisely

1. **personal `@gmail.com` auth** — the gmail wish scoped v1 to personal accounts via interactive
   oauth. `getGmailAuthAdapter.genAuth` throws `gmail has no interactive auth flow`; only a
   workspace service account reads mail. the oauth refresh path has no bootstrap
2. **429 retry/backoff** — the gmail wish, criteria, and a peer round asked for it. no gmail call
   retries a 429, and a 429 surfaces as an `UnexpectedCodePathError`. F7 records that the retry
   leaves existed unwired and were deleted as orphans
3. **first sync unbounded** — the gmail vision asked for `--since` on a first run; the first sync
   reads the whole mailbox
4. **corrupt cache** — the gmail vision promised checksum detect + re-sync of the range; the code
   fails loud instead, with no recorded divergence
5. **oauth tokens on disk** — `upsertGatherAccessToken` writes `accessToken` + `refreshToken` as
   plaintext json under `.agent/.cache/`; `getOneGatherAccessToken` reads them back as the
   credential. `rule.require.credentials-from-keyrack` read literally forbids it
6. **refresh grant never called live** — `genAuthRefresh` (`grant_type=refresh_token`) has no
   gated live case; the rotated-token branch is unproven against google

## .the shape of the fix

- 1: a wisher call first — restore interactive oauth for personal accounts, or amend the gmail
  wish to workspace-only and record the divergence
- 2: wire a bounded retry with backoff around the gmail list/get calls; surface a 429 that
  exhausts retries as a `MalfunctionError` that names the rate limit; clamp with a 429 fixture
- 3: refuse a first sync with no `--since` and no cursor, or record the divergence
- 4: record the fail-loud choice as a divergence in the gmail yield, or build the checksum
- 5 + 6 ride on 1: since `genAuth` throws, no oauth token is ever minted, so the cache and the
  refresh grant serve no caller. either delete the oauth path as an orphan (then 5 and 6 close),
  or restore interactive oauth, source the refresh token via keyrack, and add a
  `TEST_LIVE=gmail` refresh case that fails loud when its keys are absent

## .why it is not done in this round

the ses stone's wish names none of the six, and the commander scoped this pass to the ses
stone's own uncredentialed work. each needs the gmail route's wisher or its own stone.
