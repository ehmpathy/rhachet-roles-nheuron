# 🌙 dream: a full-slot `keyrack unlock` leaves some keys locked, without a word

kind: reseed · owner: ehmpathy/rhachet (keyrack) · caught 2026-11-24

## .the cue that fired

stone `5.3` live suites. `rhx keyrack unlock --owner ehmpath --org nheuron --env prep` ran and
printed only the absent keys. the live run then refused: `live run lacks its aws profile`,
then `ses config absent`. `keyrack get --key AWS_PROFILE` read `locked 🔒`. a per-key unlock of
`AWS_PROFILE` (vault `aws.config`, 55m) and the three `SES_*` keys (540m) each worked.

## .the gap, precisely

1. a slot-wide unlock does not unlock every present key in the slot, and its output does not
   say which keys it left locked
2. keys relock before the 540m their unlock reported, across one session

## .the shape of the fix

- slot-wide unlock: unlock every present key, or list each key it skipped with the reason and
  the per-key command
- record each key's unlock + relock time so an early relock is visible; clamp with a slot that
  mixes an `aws.config` key and a plain key

## .why it is not done in this round

the fix lives in rhachet. the local cure (per-key unlock) works, and the ses hint already names
`keyrack get --key AWS_PROFILE` for a human who meets it.
