# 🌙 dream: live cases for the cloudflare dns wish and the aws account triplet, behind TEST_LIVE

kind: test coverage · owner: this repo · caught 2026-11-02

## .the cue that fired

5.3 peer round i001, lane `mech-external-contracts`: no real call proves the cloudflare dns wish
or `provision/resources.accounts.ts`. gmail and ses each own a `TEST_LIVE`-gated live case;
cloudflare and the account triplet own none.

## .the gap, precisely

- `provision/cloudflare/resources.mail.dns.integration.test.ts` clamps only the refusals (absent
  keys, empty `SES_DKIM_TOKENS`); no case reads the real zone
- `provision/resources.accounts.ts` has no test at all

## .the shape of the fix

1. widen `isLiveTargeted({ mechanism })` to accept `cloudflare` and `aws.accounts`
2. a `given.runIf(isLiveTargeted({ mechanism: 'cloudflare' }))` case: build the dns resources,
   get each record from the real zone by unique, assert each declared record is found and equal.
   targeted with no token, it throws (the F8 shape)
3. a pure build test for `resources.accounts.ts` (the triplet's names, emails, parents), plus a
   `TEST_LIVE=aws.accounts` case that gets each account by unique from organizations

## .why it is not done in this round

the commander's F8 verdict bars any live call from ci absent a named flag, and this machine holds
no cloudflare token or org credential to prove a new live case runs. a live case that no one has
run once is a guess; it lands with the first human who can target it.
