# 🌙 dream: a self-review promise shows the next review but never asks it

kind: reseed · owner: ehmpathy/rhachet-roles-bhrain (driver, `route.stone.set`) · caught 2026-11-24

## .the cue that fired

stone `5.3.verification` of `v2026_07_30.collect-from-ses`, eight self reviews. after each
`--as promised`, the output read `passage = progressed (review.self N/8 promised)` and printed the
FULL guide for review N+1, with its path and the promise command to run. a review written against
that guide, then promised, was refused every time:

```
🍃 no ask on record
   ├─ this review was never asked for, or its ask was rewound
   └─ ask for it, and the guard hands you the path
      └─ rhx route.stone.set --stone 5.3.verification --as passed
```

then, after the re-ask, the same file was refused again as `🍂 that review predates the ask`.

## .the gap, precisely

the promise renders review N+1's guide but does not record an ask for it. the guide on screen
looks like an ask, so a driver writes the review, and the guard then refuses it twice: once for no
ask, once for staleness against the ask the re-run records. each review cost a wasted write, a
re-ask, and a re-write.

## .the shape of the fix

either:
- the `--as promised` path records the ask for review N+1 at the moment it renders its guide, or
- it renders only a one-line "next: run `--as arrived` to receive review N+1" and no guide

the first keeps the flow one call shorter. a clamp: promise review N, write review N+1 to the path
shown, promise it — expect accepted.

## .why it is not done in this round

the defect is in another repo's skill (bhrain driver). this route can only reseed it.
