## 🔴 blockers

### 1. missing token refresh logic — scope leak

the blueprint detects expired tokens but never shows where refresh happens.

| what exists | what's missing |
|-------------|----------------|
| `getGmailAuthStatus` → returns 'expired' | no `refreshGmailAccessToken` communicator |
| `setGmailAuth` → full oauth flow | no lightweight refresh path |

**hazard**: users with expired access token but valid refresh token will be forced through full oauth flow unnecessarily.

**fix**: add `refreshGmailAccessToken` communicator that uses refresh_token to get new access_token without browser.

### 2. body field absent from GatherMail — data model inconsistency

```
GatherMail domain object:
├─ snippet: string    ✓
└─ body: ???          ✗ missing
```

but `isSecuritySensitive` takes `{ body?: string }` as input.

**hazard**: security detection cannot run on body content because it's never stored.

**fix**: either:
- add `body: string` to GatherMail (storage cost)
- or explicitly scope security detection to snippet/subject only (reduced coverage)

### 3. token storage key pattern mismatch

| location | pattern |
|----------|---------|
| vision | `GATHER_SOURCE_{source}_ADDRESS_{hashOf(address)}` |
| blueprint | `GATHER_GMAIL_TOKEN_{hashOf(address)}` |

**hazard**: extensibility claim broken — slack/phone adapters can't follow a consistent pattern.

**fix**: unify to `GATHER_{source}_TOKEN_{hashOf(address)}` or the vision pattern.

## 🟡 nitpicks

### 4. transformer naming: `getGmailOAuthUrl` should be `asGmailOAuthUrl`

`get*` implies retrieval (communicator). this is pure computation (transformer).

follow treestruct convention: `as*` for casts/parsers.

### 5. missing sync state path transformer

`asEmailCacheKey` exists for emails, but `.sync.json` path is computed inline.

add `asSyncStateCacheKey` for consistency.

### 6. missing error detection transformers

criteria mentions extensive error cases. no transformers to detect/categorize:

| missing transformer | purpose |
|---------------------|---------|
| `isRateLimitError` | detect gmail 429 |
| `isTokenExpiredError` | detect expired token from api response |
| `isNetworkTimeoutError` | detect timeout |
| `asRecoverableErrorMessage` | format actionable error for user |

**hazard**: error handling logic will be scattered across orchestrators.

### 7. dispatchGatherMail does too much

current flow in single orchestrator:
1. parse address
2. validate auth
3. sync emails
4. format output
5. emit stdout

**hazard**: violates "orchestrators read as narrative". validation and formatting are separate concerns.

**fix**: extract `validateGmailAuth` guard and `emitGatherMailOutput` formatter.

### 8. adapter interface not blueprinted

vision promises `--from {gmail,slack,phone}` extensibility via dispatcher + adapter.

blueprint shows only gmail-specific operations. no `GatherMailAdapter` interface.

**hazard**: when slack adapter arrives, there's no contract to implement.

**fix**: blueprint the adapter interface even if only gmail implements v1:
```typescript
interface GatherMailAdapter {
  source: GatherMailSource;
  getAuthStatus: (input, context) => Promise<AuthStatus>;
  syncMessages: (input, context) => Promise<SyncResult>;
  // ...
}
```

### 9. missing sync state persistence communicator

`syncGmailEmails` says "update sync state" but no explicit `setSyncState` communicator.

either:
- add `setSyncState` communicator
- or clarify `.sync.json` writes happen in `setCachedEmail`

### 10. journey test violates blackbox principle

```typescript
// from blueprint
when('[t5] cache hit — no api call', () => {
  then('gather.mail returns cached emails instantly', () => {
    // verify no api call via latency check or mock  ← VIOLATION
```

acceptance tests must not mock. latency checks are unreliable.

**fix**: journey test should only verify behavioral outcomes:
- output contains expected emails
- output timestamp shows cache hit (if exposed)

### 11. retry/backoff not decomposed

criteria: "operation retries automatically with backoff"

no `withRetry` wrapper or retry communicator in blueprint.

**fix**: add `withRetry` wrapper per `rule.require.hook-wrapper-pattern`:
```typescript
const _getGmailMessages = async (input, context) => { ... };
export const getGmailMessages = withRetry(_getGmailMessages, { maxAttempts: 3 });
```

### 12. keyrack context interface undefined

all communicators take `{ keyrack: KeyrackClient }` but `KeyrackClient` type is never defined.

**fix**: reference actual rhachet types or define interface.

## 🟢 opportunities

### 13. decompose security detection for recomposition

current: `isSecuritySensitive` is monolithic.

opportunity: split into composable detectors:
```
isSecuritySensitive/
├─ isPasswordRelated.ts    # "password", "reset"
├─ isMfaRelated.ts         # "mfa", "otp", "2fa", "verification code"
├─ isSigninRelated.ts      # "signin", "authentication"
└─ isSecuritySensitive.ts  # composes above
```

**benefit**: future sources (slack, phone) may need different triggers. composable detectors enable source-specific security rules.

### 14. extract cache operations to reusable layer

current: `getCachedEmails`, `setCachedEmail` are gmail-specific.

opportunity: these are generic filesystem cache operations. extract to `@/access/cache/`:
```
access/cache/
├─ getOneFromCache.ts
├─ setOneToCache.ts
├─ getAllFromCache.ts
└─ getCachePath.ts
```

**benefit**: slack/phone adapters reuse same cache infrastructure.

### 15. address parsing is adapter-agnostic pattern

`asAddressScope` parses `vlad@gmail.com/labels=work,urgent`.

this pattern (`{base}/{scope}`) applies to:
- slack: `ehmpathy/channel=general`
- phone: `+1-555-1234`

**opportunity**: extract `asAddressWithScope` generic transformer, let adapters define scope schemas.
